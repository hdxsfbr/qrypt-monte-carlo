Lifecycle of a job's status. Only three values are ever stored (QUEUED, COMPLETE, PARTIAL); RUNNING is derived in api.view for a QUEUED job once any shard has been recorded. COMPLETE and PARTIAL are terminal (store.FINISHED). Transitions out of QUEUED all go through store.finish_job, a conditional update requiring status = QUEUED, so concurrent finishers (the last worker, a retrying worker, a stale GET) cannot overwrite each other. Replay does not change the original job; it creates a new QUEUED job linked by replay_of.
