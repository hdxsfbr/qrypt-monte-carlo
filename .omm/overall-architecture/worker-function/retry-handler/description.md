Failure path of process() plus retry_soon() in src/handlers/worker.py. On each failure it shortens the message visibility to 2^attempt seconds (2, 4, 8; capped at 300) so retries happen quickly. On the final attempt (attempt >= MAX_RECEIVE_COUNT) it first records the shard as FAILED (incrementing the failed counter, ShardFailures metric) and calls maybe_finish, so the job ends PARTIAL instead of waiting; the message then goes to the DLQ.
